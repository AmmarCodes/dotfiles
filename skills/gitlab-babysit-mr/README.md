# gitlab-babysit-mr

Monitor a GitLab MR's pipeline until green. Retries flaky/broken jobs, auto-fixes lint, and posts a structured report as an MR comment.

## Dependencies

- [`glab`](https://gitlab.com/gitlab-org/cli) CLI — authenticated
- [`jq`](https://jqlang.github.io/jq/)
- `gitlab-pipeline-watch` skill — provides `pipeline-watch.py` for blocking pipeline polling

## Opinionated defaults

This skill ships with specific opinions baked in. They reflect one workflow; yours may differ.

| Decision | What the skill does | Why you might change it |
|---|---|---|
| **Max 5 action rounds** | Caps retries/fixes at 5, but waits indefinitely for running pipelines | Fewer rounds for faster feedback, or more if your project has many flaky jobs |
| **Auto-fix lint and push** | Runs `rubocop --autocorrect`, `eslint --fix`, `haml-lint --auto-correct` on changed files, commits, and pushes | You might prefer to only report lint failures. Or you use different linters (e.g. `biome`, `black`) |
| **Retry flaky jobs up to 2×, then pipeline** | Retries any `FLAKY`-classified job up to 2 times. On the 3rd failure of the same job, escalates to a full pipeline retry | You might want fewer retries, or to require a known flaky-test issue before retrying |
| **Retry entire pipeline for master-broken** | If a failure is in code the MR didn't touch, retries the whole pipeline | You might prefer to just report it and wait for someone to fix master |
| **Resolved discussion thread** | Creates a single resolved discussion ("Thread generated by `/gitlab-babysit-mr`") and posts all reports as replies inside it, keeping the MR discussion clean | You might prefer a visible top-level comment, or no comments at all |
| **Diagnoses blocking failures before exiting** | When blocked (REAL_FAILURE, MASTER_BROKEN, UNKNOWN, REQUIRES_MANUAL_FIX), analyzes root cause and includes fix suggestions in the final report | You might prefer a quick exit without diagnosis |
| **Ruby/JS/HAML linters** | Only knows about RuboCop, ESLint, Prettier, and HAML-lint | If your project uses other linters, those failures will classify as `UNKNOWN` |

## Customizing with agent prompts

If you don't want to fork the skill, override defaults by telling your agent what to do differently when you invoke it:

```
/gitlab-babysit-mr https://gitlab.com/myorg/myproject/-/merge_requests/456
Do NOT auto-fix lint failures. Classify them but take no action — just include them in the report.
```

Overrides compose naturally:

```
/gitlab-babysit-mr https://gitlab.com/myorg/myproject/-/merge_requests/101
- Skip auto-fixing lint, just report
- Only retry flaky jobs with a known issue
- Post the report to stdout, not as an MR comment
- Max 3 action rounds
```
